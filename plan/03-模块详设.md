## 一、统一中间表示（台账）

全项目只有一套"变动台账"形状；M2 产持仓、M3 产变动、M4 产事件、M5 只消费。字段名一旦冻结（K 编号），改字段 = 改契约版本。

### 1.1 `watchlist`（M1，本地存储）

```json
{
  "schema": "funddiff/watchlist@1",
  "funds": [
    {"code": "000001", "name": "华夏成长混合", "added_on": "2026-10-18", "note": null}
  ]
}
```

- 唯一键 `code`；重复添加 = **幂等更新**（不新增条目，`added_on` 保留首次值）。
- 全表按 `code` 升序；`name` 可为 `null`（映射未命中时不允许编造）。
- 文件路径默认 `local_data/watchlist.json`，**不入仓**。

### 1.2 `holdings`（M2 归一持仓，单基金单季）

```json
{
  "schema": "funddiff/holdings@1",
  "fund_code": "000001",
  "report_period": "2026Q3",
  "period_end": "2026-09-30",
  "source": {"channel": "json|page", "endpoint": "FundMNInverstPosition|jjcc",
             "fetched_at": "2026-10-18T09:00:00Z", "raw_sha256": "…"},
  "rows": [
    {"stock_code": "688361", "stock_name": "中科飞测", "ratio": "9.80",
     "change_type": "减持|null", "change_pct": "-0.09|null",
     "industry": "电子|null",
     "raw": {"ratio": "9.80%", "change_type": "减持", "change_pct": "-0.09"}}
  ],
  "structural_note": null,
  "status": "ok|empty|failed|structural_mismatch"
}
```

纪律：

- `ratio` / `change_pct` 是**字符串十进制**，不是 float；`null` 表示缺失，**绝不写 `0`**。
- `raw` 保存接口原始字段值，供溯源；`source.raw_sha256` 指向本地原始响应快照。
- `status=empty` 仅用于"结构上无股票持仓"（ETF 联接 / QDII），**与 `failed` 严格区分**；`structural_note` 写差异说明。
- `rows` 排序：`ratio` 降序 → `stock_code` 升序。

### 1.3 `diff_entry`（M3 变动台账，核心）

```json
{
  "schema": "funddiff/diff@1",
  "mode": "provider|computed",
  "threshold": "0.10",
  "fund_code": "000001",
  "report_period": "2026Q3",
  "prev_period": "2026Q2",
  "entries": [
    {
      "stock_code": "688361",
      "stock_name": "中科飞测",
      "prev_ratio": "8.42",
      "cur_ratio": "9.80",
      "delta": "1.38",
      "status": "新进|退出|加仓|减仓|不变|待确认",
      "basis": "provider|computed|both_conflict|insufficient_data",
      "provider_change_type": "增持",
      "provider_change_pct": "1.38",
      "trace": {
        "prev": {"source": "…", "report_period": "2026Q2", "field": "JZBL", "value": "8.42", "raw_sha256": "…"},
        "cur":  {"source": "…", "report_period": "2026Q3", "field": "JZBL", "value": "9.80", "raw_sha256": "…"}
      }
    }
  ],
  "summary": {"新进": 1, "退出": 0, "加仓": 3, "减仓": 2, "不变": 4, "待确认": 0},
  "conflicts": [
    {"stock_code": "…", "provider": "增持", "computed": "减仓", "note": "…"}
  ]
}
```

排序：`report_period` 内按 `fund_code` → `cur_ratio` 降序（`null` 排末尾）→ `stock_code`。

### 1.4 `events`（M4 经理 + 规模）

```json
{
  "schema": "funddiff/events@1",
  "fund_code": "000001",
  "report_period": "2026Q3",
  "managers": [
    {"name": "…", "start": "2012-09-28", "end": null,
     "change_date": "2026-06-27", "in_period": true,
     "change_class": "in_period|prior_period|none|unparsed",
     "source": "jjjl", "raw_text": "…"}
  ],
  "scale": {
    "report_period": "2026Q3",
    "subscribe": "1.49", "redeem": "3.36", "shares": "24.06",
    "net_assets": "39.38", "share_change_rate": "48.93%",
    "baseline": "available|no_prev_baseline",
    "units_from_header": {"subscribe": "亿份", "net_assets": "亿元"},
    "source": "gmbd", "raw_sha256": "…"
  }
}
```

纪律：

- `change_class` 是**事件分类**，不是能力评价；字段里禁止出现任何评分/排名类键。
- `baseline=no_prev_baseline` 时金额字段可为 `null`，**不得填 0**。
- 单位从接口表头读取后原样记录，不在代码里写死。

```json
    "diff_mode": "computed", "threshold": "0.10",
    "report_period": "2026Q3", "period_start": "2026-07-01", "period_end": "2026-09-30",
    "as_of": "2026-10-18", "data_notes": ["…"],
    "generated_fields": []

```

`report.md` / `report.html` 与本文件**同源**：三份产物由同一个内存模型渲染，任何一份里的数字都能在 JSON 中找到。

## 二、M1 清单与窗口

### 2.1 命令

| 命令 | 语义 | 退出码 |
|---|---|---|
| `watch add <code> [--name N] [--note T]` | 幂等添加/更新 | 0；非法代码 2 |
| `watch list [--json]` | 列清单（默认表格，`--json` 机读） | 0 |
| `watch remove <code>` | 删除；不存在 → 0（幂等）或 1？**定案：不存在返回 1 并打印"未在清单中"** | 0/1 |
| `window [--as-of YYYY-MM-DD] [--json]` | 输出本期报告窗口与逐基金披露状态 | 0；日期非法 2 |

> `watch remove` 的"不存在返回 1"是**谓词语义**（"确实删掉了一条"为真才 0），与 skill 的退出码纪律一致；README 明示。

### 2.2 窗口模型

```
季度 → 报告期截止日（Q1 03-31 / Q2 06-30 / Q3 09-30 / Q4 12-31）
报告期起始 = 上一报告期截止日次日
本期 = as_of 所属的报告期（若已过披露截止则为本期，否则仍为本期"待披露"）
披露状态 ∈ {已披露, 待披露, 无数据}
```

- **`已披露`**：官方元数据（`eid`）中存在该 `fund_code + 报告期` 的记录。
- **`待披露`**：元数据可访问，但没有该记录。
- **`无数据`**：元数据获取失败（网络/解析），且**不得与"待披露"合并**。
- 三者计数进 `report_data.json.totals`，未披露基金不报错、不跳过而不留痕。

### 2.3 `--as-of`

- 传参即固定判断基准日，**不读系统时钟**；
- 不传时取当天并在输出 `as_of` 字段打印；
- 历史日期复跑必须与当日快照一致（窗口与状态均由配置 + 元数据快照决定）。

### 2.4 代码→名称映射

- 按需缓存 `cache/fund_codes.json`（gitignore）；未命中才联网；
- 缓存命中 → 零网络请求（测试用 socket 拦截证明）；
- 拉取失败不影响已缓存条目，未命中项 `name=null`。

## 三、M2 持仓抓取与归一

### 3.1 双通道判定

```
try JSON 通道(FundMNInverstPosition)
  ├─ 字段齐全（GPDM/GPJC/JZBL 至少三项）→ channel=json
  └─ 缺失/空/结构不符 → 记录 fallback_reason，转页面通道
try 页面通道(jjcc, GBK, 内嵌 JS 正则)
  ├─ 解析出 ≥1 行 → channel=page
  ├─ 0 行且基金类型属"结构性无股票持仓" → status=empty, structural_note
  └─ 0 行且非结构性 → status=failed
```

- **回落必须留痕**：`source.fallback_reason` + 报告显示"本条来自页面解析"。
- **编码纪律**：`jjcc` 一律 `gbk` 严格解码；`UnicodeDecodeError` → 保存原始字节到 `snapshots/`、`status=failed`、`error=decode_error`，**禁止 `errors="ignore"`**。
- **字段归一**：去 `%`、去全角空格、保留符号；名称不做字符替换（只做空白清洗）；`industry` 缺失 → `null`。

### 3.2 失败隔离与退避

- 逐基金 `try/except`，单只失败写 `fetch_status` 台账（`ok/empty/failed/structural_mismatch` + `error_kind`）；
- 重试：指数退避，参数（初始间隔/倍率/上限次数/最大总等待）全来自配置；
- 命中 429/403/验证码/登录 → 该域名后续请求全部停止，整体 exit 4，已成功基金结果保留。

### 3.3 验收用例（M2 DoD）

1. JSON 通道与页面通道在同一基金上的**股票代码集合一致**；
2. 联接基金 → `status=empty`，exit 0；
3. 单只网络失败 → 其它基金结果不受影响，失败台账可读；
4. 构造 GBK 非法字节 → `decode_error` 且原始字节落盘。

## 四、M3 Q/Q diff 引擎

### 4.1 状态机（闭合五态 + 待确认）

```
输入：prev_holdings, cur_holdings, mode, threshold

对股票代码全集逐一：
  prev 无, cur 有           → 新进
  prev 有, cur 无           → 退出
  prev 有, cur 有:
     mode=provider:
        provider_change_type ∈ {增持, 减持, 不变} → 加仓/减仓/不变
        缺失或不可识别 → 待确认 (basis=insufficient_data)
     mode=computed:
        |Δ| < threshold  → 不变
        Δ > 0            → 加仓
        Δ < 0            → 减仓
        Δ 不可算（任一 ratio 为 null） → 待确认
```

- **无第六态**：不能判定一律 `待确认`，计入 `summary.待确认` 与报告计数。
- **冲突检测**（两模式都可用时）：provider 方向与 computed 方向相反 → 写入 `conflicts[]`，**不覆盖主判定**（主判定由 `mode` 决定），报告列"口径冲突"清单。
- `delta` 由 `cur_ratio - prev_ratio` 计算（Decimal），保留两位；`null` 参与 → `delta=null`。

### 4.2 可溯源性

每条 entry 的 `trace.prev` / `trace.cur` 必含：`source`（通道+端点）、`report_period`、`field`、`value`（原始字符串）、`raw_sha256`。M3 基准抽查：任取一条，能定位到两份原始记录。

### 4.3 确定性

- 排序固定（见 §1.3）；
- 同一输入双跑，`diff.json` 逐字节一致（测试锁定）；
- `threshold` 以字符串写入产物，保证字节稳定。

## 五、M4 经理变更与规模变动

### 5.1 经理变更解析

来源：`jjjl` 页面（UTF-8）。

| 解析目标 | 页面锚点 | 失败处理 |
|---|---|---|
| 变动区间 + 姓名 + 天数 + 任期回报 | "基金经理变动一览"表格行 | 解析不到 → `change_class=unparsed` + 页面快照，**不猜** |
| 上任日期 | "现任基金经理简介" | 同上 |

`change_class` 判定（区间来自配置，不读当天）：

| 条件 | 分类 |
|---|---|
| `change_date ∈ [period_start, period_end]` | `in_period`（本季内变更） |
| `change_date < period_start` 且上一次报告期内 | `prior_period`（上季末已变更） |
| 无变动记录 | `none` |
| 解析失败 | `unparsed` |

**合规**：姓名只作事件主体标识。字段与模板中禁止出现"能力/排名/业绩归因"类表述；M5 合规门禁兜底。

### 5.2 规模变动

- 六字段（报告期/申购/赎回/份额/净资产/变动率）**分别入台账**，不混算；
- 单位读表头原样记录；
- 新成立基金无上季 → `baseline=no_prev_baseline`，金额 `null`；
- **0 与缺失可分**：`0` 是真实数值，`null` 是缺失；测试各构造一例。

### 5.3 验收

三类经理样本（in_period / prior_period / none）标注正确；`unparsed` 有快照；规模 `0` 与 `null` 可区分。

## 六、M5 报告与合规门禁

### 6.1 产物

| 文件 | 说明 |
|---|---|
| `report.md` | 人读；按基金分组；含口径页眉与固定页脚 |
| `report.html` | **单文件**：无 `<script src>`、无 `<link>`、无 `http(s)://`、无 `//` 协议相对引用；内联 CSS |
| `report_data.json` | 机读；三产物同源 |

### 6.2 报告结构

```
页眉：口径（provider/computed + threshold）/ 报告窗口 / 数据基准日 as_of / 抓取时间戳
按基金：
  披露状态
  变动摘要（五态 + 待确认计数）
  变动明细（含"来源：基金季度报告"）
  经理变更（含"来源：基金定期报告公开披露"）
  规模变动（四条口径分列）
  口径冲突（如有）
与上期报告对比（若提供 --prev-report）：新增基金 / 本期无变动基金 / 累计变动
页脚（冻结）：非投资建议 · 来源：基金季度报告
```

### 6.3 合规门禁

- 词表来自配置（唯一来源 `data/README.md §四.4`），**代码零硬编码**；
- 扫描面：`report.md` 正文 + `report.html` 可见文本 + `report_data.json` 展示字段；
- 归一：大小写 + 全半角 + 空白；
- 命中 → **exit 1**，输出 `文件:行:命中词`（词面从配置读，日志打印命中位置与词）；
- `--check-compliance` 只检查不生成；`report` 默认生成后即检查。

### 6.4 零外链

扫描 HTML：`<script src`、`<link`、`http://`、`https://`、`src="//`、`url(` 中的外链形态。0 命中才能 exit 0。

### 6.5 零判定渲染

`report.py` 不得 import `diff` / `managers` / `scale` 的判定函数；AST 守门断言 `report.py` 内不出现 `if … status ==` 类判定分支——判定只来自 model。M0 先立规则，M5 落测试。

## 七、CLI 契约总表

| 子命令 | 参数 | 阶段 | 骨架期退出码 |
|---|---|---|---|
| `watch add/list/remove` | `<code>`、`--name`、`--note`、`--json` | M1 | 0 / 2（已实现） |
| `window` | `--as-of`、`--json` | M1 | 0 / 2（已实现） |
| `fetch` | `--fund`、`--period`、`--as-of` | M2 | 3 |
| `diff` | `--mode`、`--period`、`--fund` | M3 | 3 |
| `managers` | `--fund`、`--period` | M4 | 3 |
| `scale` | `--fund`、`--period` | M4 | 3 |
| `report` | `--out-dir`、`--period`、`--check-compliance`、`--prev-report` | M5 | 3 |
| `run` | `--as-of`、`--out-dir` | M5 | 3 |
| `selftest` | `--data-dir`、`--json` | M0 | 0 通过 / 1 检查失败 / 2 数据目录不可用 |

全局参数：`--store PATH`、`--data-dir PATH`、`--json`（部分子命令）。

约定：

- 未知子命令 → exit 2（argparse 默认 2，保留）；
- 参数值非法（基金代码非 6 位数字、日期非法）→ exit 2；
- 骨架期 stub **必须**打印"该阶段尚未实现（Mx）"到 stderr 并 exit 3。
- `selftest` 的 `1` 只表示"检查跑了但结论不达标"；数据目录/配置不可用是 `2`（自检**未运行**）。这条区分是刻意的：否则用户分不清"没跑起来"和"跑了没过"。

## 八、K 清单（既定口径，动了会打挂基准）

| 编号 | 约定 | 生效 |

| K1 | `serialize.write_json` 是唯一写盘出口；`sort_keys` + `ensure_ascii=False` + `indent=2` + LF + 结尾换行 | M0 |

| K4 | 业务逻辑不读系统时钟；`--as-of` 决定窗口 | M0 |
| K5 | 退出码 0/1/2/3/4/5 语义（见 plan/02 §四） | M0 |

| K7 | 配置必须显式给 `diff.mode`，取值 `provider|computed`，无缺省推断 | M0 |
| K8 | 台账排序：基金代码 → 占比降序 → 股票代码 | M1 |
| K9 | 五态闭合 + `待确认` 计数，无第六态 | M3 |
| K10 | 合规词表只在配置中定义，代码零硬编码 | M1（配置） |
