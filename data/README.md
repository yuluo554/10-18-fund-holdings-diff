### 1.4 数据源策略（定案）

```
证监会 eid（判断"这份季报发了没有"）
        ↓ 只对已披露的基金
东财（补"里面写了什么"：持仓 / 规模 / 经理）
        ↓
交叉校验（持仓代码集合、报告期一致性、口径冲突清单）
```

**顺序不可颠倒**：先用官方元数据确定披露状态，再决定是否抓明细。这样既避免对未披露基金的空抓，也让"待披露"有权威依据。

**ToS 边界（硬约束）**：东财仅个人本地低频使用；**不建公开镜像、不再分发原始数据、不把抓取结果提交进仓库**。仓库内样例一律为合成快照（见 §三）。

## 三、合成数据纪律

**核心原则：仓库内不出现真实抓取的全量数据。**

1. **合成两季快照**：由生成器产出 `fund_snapshot_qprev` / `fund_snapshot_qcur` 两份配对快照，覆盖：
   - 五类变动：新进 / 退出 / 加仓 / 减仓 / 不变；
   - 三类经理状态：本季内变更 / 上季末已变更 / 无变更；
   - 三类规模状态：正常变动 / 新成立无上季基准 / 期间零申赎；
   - 三类结构差异：普通股票型 / 混合型 / ETF 联接（无股票持仓）。
2. **样例基金代码必须标注为"快照样本"**：可以沿用真实代码形态（便于格式校验），但**数据值必须是程序化合成的**，且在快照文件头与报告中标 `sample: synthetic`。**不得把真实抓取的一次响应原样提交**。
3. **真值由生成器同源产出**：真值台账只存"输入 + 期望变动状态"，观测值由基准运行时实算；**禁止手改真值**，改动走整目录重生成 + `--check` 位级守门。
4. **真值覆盖按类型登记**：`coverage` 段逐类型登记 `total / sampled`，显式声明"抽样覆盖、非穷举"；分子 = 分母由测试锁定，不写会漂移的绝对数字。
5. **异常样本程序化注入**：缺字段、占比为空、股票代码异常、页面解析失败、网络失败，各构造至少一例，用于验证失败隔离与待确认队列。
6. **联网抓取的产物落本地 `snapshots/` 目录并 gitignore**：可复跑、可核对，但**永不入仓、永不发布**。

## 四、数值口径纪律（唯一权威定义处）

> 以下四项**只在本节定义一次**。代码常量、报告文案、基准门槛均引用本节，禁止二次定义。

### 4.1 变动判定口径

`diff.mode` 二选一，**必须在配置中显式指定，不允许缺省时自动猜**：

| 模式 | 判定方式 | 适用 |
|---|---|---|
| `provider` | 直接采用接口 `PCTNVCHGTYPE`（增持 / 减持 / 不变）与 `PCTNVCHG` | 接口字段齐全时（首选） |
| `computed` | 用两季 `JZBL` 之差 Δ 判定：`|Δ| < threshold` → `不变`；`Δ > 0` → `加仓`；`Δ < 0` → `减仓` | 接口缺字段、或需交叉校验时 |

- **`threshold` 默认值与上下限在实现期冻结进配置包**，本文不写死具体数值（避免与实现漂移）；取值依据为"季报占比通常保留两位小数，低于最小显示精度视为不变"。
- 五态闭合：`新进 / 退出 / 加仓 / 减仓 / 不变`；**无法判定 → `待确认`，计入报告计数，不算第六态通过**。
- `provider` 与 `computed` 方向相反时 → 记入**口径冲突清单**，两份值都保留，不取平均、不静默择一。

### 4.2 季报窗口定义

- 报告期：`Q1 → 03-31`、`Q2 → 06-30`、`Q3 → 09-30`、`Q4 → 12-31`（**报告期截止日**）；
- 披露窗口：**Q3 报告期截止 9/30、披露截止 10 月底**（题面给定的制度事实，与本项目实测到的"Q3 报告在 10 月内陆续发布"一致）；
- ⬜ **待核**：Q1 / Q2 / Q4 对应的法定披露期限（工作日起算方式）须在实现前按《公开募集证券投资基金信息披露管理办法》原文核对后写进配置。**本文件不在未核对时给出天数，也不把推测写成规则**；
- 「本期报告窗口」= 目标报告期 + 其披露截止日，**写入配置**；未核实的季度窗口配置值必须标注 `unverified: true`；
- **`--as-of` 语义**：把工具固定在指定日期上判断披露状态与窗口，**不读系统时钟做隐式判断**；缺省 `--as-of` 时取系统日期但**在报告中打印实际使用的日期**。
- 「本季内变更」= 变更日期 ∈ `[报告期起始, 报告期截止]`；`报告期起始` = 上一报告期截止日的次日。

### 4.3 限频与退避

- 单次运行对同一域名的请求**串行化**，相邻请求之间插入固定最小间隔；
- 失败重试采用**指数退避**：初始间隔、倍率、最大重试次数、最大总等待**全部在配置包一处定义**；
- 命中 HTTP 429 / 403 / 验证码 / 登录跳转 → **立即停止该域名下的后续请求**，落台账并提示用户稍后重试，**不做任何规避**；
- 抓取结果按 `(source, fund_code, report_period)` 缓存，**同一运行内不重复请求**；跨运行缓存供离线复跑。

### 4.4 合规词表

报告中**不得出现**（大小写、全半角归一后匹配）以下表述：

```
抄作业、跟随基金经理、跟买、推荐、买入、卖出建议、抄底、必涨、稳赚、包赚、
跑赢、牛基、神基、明星基金经理、闭眼买、上车
```

- 匹配范围：`report.md` 正文 + `report.html` 可见文本 + `report_data.json` 的展示字段；
- 命中 → **非零退出**，输出 `文件:行:命中词`；
- 词表实现期冻结进配置包；新增词走配置版本升级，**不得在代码里硬编码第二份**。
- 例外：**对词表本身的说明性引用**（如本文档、README 的边界章节）不参与扫描；扫描只针对生成产物。

### 4.5 确定性约定

- 台账排序：基金代码升序 → 本季占净值比降序 → 股票代码升序；
- JSON 输出：键序固定、浮点按统一精度序列化；
- 同一输入两次运行的 `report.md` / `report.html` / `report_data.json` **字节一致**（时间戳类字段除外，须单独列明并固定格式）。
